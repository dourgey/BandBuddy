# BandBuddy 性能、界面与环境优化交付记录

本次工作保留原有功能和工作区已有的练功房扩展，代码位于 `codex/performance-environment-themes`。以下区分已经实现、在本机验证，以及仍需发布设备验证的事项；性能目标不是所有环境的保证值。

## 已实现的主要改动

### 启动与运行性能

- 常规启动不再同步备份整库；只有需要迁移时才创建包含 WAL 内容的一致性备份。新增数据库查询索引、SQL 筛选、批量摘要与分页，曲库按视口绘制；最近练习使用独立查询。
- 同一窗口先显示可最小化、关闭的启动界面，再准备数据库。首次迁移和中断状态恢复移到工作线程，已迁移库走轻量快速路径；服务 IPC 等待注册完成后再执行，失败保留明确的启动错误。首帧外观从只读配置读取，旧配置默认暖色。
- 工具哈希和签名验证异步复用同一结果，实际执行工具前等待验证通过。分轨环境和声卡探测不阻塞曲库；已有健康缓存可快速恢复状态。首次迁移独立验证，没有混入已迁移库的热启动基准。
- PCM 波形统计、BPM 与调性算法移至独立工作线程；关闭应用时等待工作线程和子进程退出。日志使用有界异步队列，任务进度合并，终态即时通知；进度与终态按任务 ID 更新缓存，环境下载进度不再反复读取整张任务表。
- 播放位置和录音电平分别局部订阅，静态页面不再订阅音频时钟。波形数据统计复用，隐藏或停止时停掉不必要的动画；切歌加载使用代次检查，避免旧请求覆盖新歌曲。
- 启动界面使用约 4kB 的入口脚本，React 主应用的代码加载与数据库准备并行，但只在服务就绪后挂载；已有权威外观快照时不再等第二次外观 IPC。生产前端启用压缩并保留 source map。练习室、排练房、军火库、练功房及大型弹窗按需加载。保存练习位置使用歌曲级缓存更新，不再广播整库失效。搜索约 150ms 防抖，并等待中文输入法提交。
- 页面首次进入后保留正在工作的音频会话；播放与录音可跨页持续，隐藏页面暂停无关绘制。全局提供返回、停止保存和取消录音，排练录音支持暂停／继续；准备、取消和立即重录按操作代次处理，避免迟到回包误开录音。

### 兼容性与安装

- 子进程连续解码 UTF-8，原生 Windows 音频程序采用宽字符入口及文件路径；取消等待进程树结束，输出保留上限并设超时。
- Electron、uv、Python 共享系统／手动／直连策略。PAC 按请求域名解析；显式代理失败时不会悄悄改为直连。国内源失败后使用限定的可信备用源，保留固定版本、哈希及续传。
- Python 环境在独立版本目录安装、自检后原子切换，失败保留旧环境，不移动已经创建的虚拟环境。首次准备入口直接放在任务面板，支持进度、取消与重试，未准备分轨环境仍可使用其他功能。
- 数据目录迁移先检查空间、权限、冲突及源文件变化，复制后逐文件验证，再提交配置；失败回滚新内容并保留原始文件。未变更的外接目录失联不会因外观保存而被重建或删除。
- 依据内存和可用显存控制线程及批量；大缓冲使用磁盘映射。保留六轨模型与吉他质量档位，不以降质代替资源适配。
- 增加 Intel CPU 依赖入口、原生 x64 wheelhouse CI、完整含哈希锁文件的生成与消费、双架构包和签名检查。真实 wheel 清单缺失时阻止 Intel 发布和安装；没有以占位哈希伪装可用产物。默认发行保留 Windows 和 Apple Silicon，Intel 明确启用后要求全部所选架构通过。
- Intel 数值验收逐一对比六轨及三个吉他档位的 15 个输出，绑定输入、模型、推理代码、依赖与参考哈希，阈值固定。本机 CPU 已生成真实参考并独立重复推理通过；它只证明 ARM CPU 可重复性，不能替代 Intel 验收。

网络、迁移、依赖及 CPU 推理的具体说明见 [运行环境验证记录](runtime-robustness.md)。

### 界面与外观

- 保留暖纸色与黑胶视觉，压缩标题、最近练习和装饰占用。五个主导航及原有功能入口保留；曲库翻页、最近练习翻页、军火库和练功房侧栏收起可用。
- 建立暖色／深色／系统主题，普通／紧凑密度，标准／精简效果。采用版本化 `appearance.get/set/onChanged` 窄接口，外观更新不触发目录迁移、设备扫描或 Python 检测。
- 主题变量覆盖表面、文字、边框、状态、焦点及波形、谱面、指板和琴键。Canvas、SVG、WaveSurfer 更新颜色时不重新加载歌曲或建立音频引擎。
- 自定义选择器支持键盘、长列表、屏幕边缘避让和弹窗层级；统一复选框、滑块、输入、确认／输入弹窗与录音预览播放器。系统文件选择及权限交互继续使用系统设施。
- 主窗口、桌面歌词与 LAN 使用统一主题；LAN 只同步主题、密度和效果字段，沿用鉴权与来源检查，系统模式由各设备自身系统解析。断开连接保留当前外观。
- 窗口恢复尺寸限制在当前屏幕工作区内。800×500 下重排播放栏、队列和设备区，次要面板可收起，正文保持可读字号。字体和图标无需远程加载。
- CSS 组件层顺序固定，避免按需加载的页面样式覆盖统一控件。减少动态效果同时遵循应用设置和系统设置。
- 录音过程中可以浏览、搜索与调整外观；换曲、试听、调音、监听及设备修改由统一会话状态保护。设置入口此时打开独立外观面板，避免外观操作扫描或变更音频设备。

后续换肤的变量分层、窄接口、Canvas／SVG 更新方式与组件约束见 [外观开发指南](appearance.md)。

## 性能实测

Apple M4、16GB、macOS arm64；优化前后每个曲库规模各 10 次，另各一次预热不计入。使用开发 Electron 加载生产 bundle、已迁移的独立数据库和热文件缓存，未安装 Python／模型环境。

| 曲库 | 可操作启动中位数：优化前 → 后 | 改善 | 优化后 p95 |
| --- | --- | --- | --- |
| 0 首 | 537.90 → 531.13 ms | 1.3% | 566.42 ms |
| 1,000 首 | 769.74 → 554.17 ms | 28.0% | 583.43 ms |
| 10,000 首 | 3,729.86 → 626.97 ms | 83.2% | 634.55 ms |

空曲库及 1,000 首未达到缩短 30% 的目标。0／1,000 首场景的后台检测完成中位数分别增加约 234／257ms；前台可操作时间缩短，不代表每项后台工作都更快。窗口先显示启动界面，曲库可操作仍按实际查询和绘制完成判定。完整数据见 [启动基准](startup-benchmark-2026-09.md) 及 [66 次原始记录](benchmarks/startup-2026-09.json)。

800×500 开发预览中的一次人工交互抽样，由 Chromium Event Timing 采集到 32 个达到 16ms 上报阈值的交互，p95／最大值均为 88ms。包括切页、侧栏、主题、选择器、钢琴示范、搜索和列表切换；按同一 interactionId 的最大持续时间计数，未使用工具调用耗时。这只是局部证据，不代表大曲库、真实多轨录音负载或正式安装包的全部交互达到目标。[原始采样及重现方式](benchmarks/interaction-2026-09.json)

## 发布前仍需完成的验收

- Windows x64、Intel macOS 13+ 的真实签名安装包、干净用户环境及独立启动验证；Intel 必须实际完成六轨和三个吉他分轨路径，并与 CPU 基准比较输出。当前 Apple Silicon 的成功不作为 Intel 支持声明。
- 国内实际受限网络、企业代理和 PAC、下载中断重启、真实磁盘空间不足、权限拒绝与外接盘掉线。自动化覆盖逻辑与故障注入，不能代替全部真实组合。
- 8GB 低内存、无独显／显存不足、真实 USB 声卡拔插、麦克风授权拒绝、长音频峰值资源占用。
- Windows 125%／150%／200% DPI 与多显示器、三个平台下持续录音过程中换肤／缩放。800×500 浏览器逻辑视口不等同于全部系统 DPI 验证。
- 常规交互 p95 ≤100ms 的完整验收仍需正式安装包及真实音频负载测量；目前仅有开发预览的 Event Timing 抽样。

## 最终检查结果

- 完整 TypeScript 检查通过；完整 Vitest 回归为 **100 个文件、590 项测试通过、1 项跳过**。包括启动排队与失败处理、播放时钟隔离、快速切歌竞态、跨页播放／录音、取消后立即重录、外观并发更新、中文搜索、目录迁移及回滚。
- `pnpm build` 通过，生产构建完整性检查通过。页面和大型弹窗独立拆包，开发用交互采样模块未进入生产输出。
- 实际 Electron 生产 bundle 在独立的中文、空格、括号和 emoji 数据路径下首次启动成功；启动界面先可见，数据库工作线程完成初始化，主预加载 API、媒体工具完整性和桌面歌词接口正常，进程完成清理后以 0 退出。该检查使用本机开发 Electron，不等于签名安装包验收。
- 本机原生音频重新编译与特殊路径模拟、Python worker 和吉他流水线验证结果见 [运行环境记录](runtime-robustness.md)。模拟设备不能代替真实声卡录音和拔插。
- 浏览器实际检查覆盖 1280×720、800×500 的曲库、练习室、排练房、军火库、练功房、设置弹窗、暖色／深色及谱面；LAN 在 390×844 逻辑视口无水平溢出。实际 WebAudio 钢琴示范切到曲库后持续播放，返回时进度继续推进。浏览器示例音源不用于证明原生多轨录音正常。
- 保留工作区已有练功房扩展；未发布安装包，也未向外部上传模型、参考音频或用户数据。
