# 原生音频与本机效果插件

本次迁移在现有 RtAudio / PortAudio 设备后端上增加原生播放时钟、独立插件宿主和录音保护。界面仍使用 Electron / React。原生练习室播放通过设置开关逐步启用；这份文档区分已经接入的代码与正式发布前仍需完成的验收，不表示升级方案的所有阶段已经完成。

## 使用入口

在「设置 → 练习室播放引擎」选择「原生引擎（预览 · 立体声）」，停止播放后重新打开歌曲。该模式由原生核心读取 stem 和录音轨、执行 seek、A–B 循环、节拍器及 EQ。变速、移调和录音轨效果先在后台准备缓存。

在「军火库 → 本机效果插件」扫描已安装的插件，或添加自定义目录。扫描只加载验证组件，不打开声卡输出。可以搜索插件、多次添加同一插件、改变处理位置、旁路、打开原生编辑器或通用参数面板。保存状态或保存音色预设会保存插件自身的完整状态。

插件扫描在录音、监听和原生播放停止时进行。缺失、版本变化或扫描失败的插件不会被静默替换。停止监听后可以重新验证被隔离的组件。声卡仍在军火库底部选择；输入与输出可分别配置。

## 进程和时钟边界

| 模块 | 职责 |
| --- | --- |
| `src/main/audio-host.ts` | 控制协议、能力校验、会话管理和插件进程切换 |
| `src/main/native-audio.ts` | 准备播放文件、提交图与控制指令、转发原生播放状态 |
| `native/audio-host` | 设备、输出主时钟、原生多轨播放、原始干声写盘、输出保护与诊断 |
| `native/plugin-host --scan / --scan-au` | 独立进程扫描；AU 使用系统组件枚举 |
| `native/plugin-host --worker` | 每条效果链一个独立进程，管理内置效果和第三方插件、原生窗口及状态 |
| `native/plugin-host --render` | 使用相同串行图创建独立离线实例，处理延迟与尾音 |
| `native/audio-ipc` | 固定容量共享内存、序号、代次、时间信息与缺损区间 |

新原生练习室路径只通过 JSON 发送控制指令，连续音频不经过 Renderer。兼容引擎和排练室仍保留现有 Web Audio / PCM 桥接；本次没有把所有桌面功能强制迁移。

Core 控制协议为 2，插件共享内存协议为 1。启动插件链或原生时间线前校验能力。Core 在结束会话、关闭设备回调并解除共享内存映射后确认关闭，随后 Supervisor 清理插件进程和临时目录。

主时钟来自输出设备。可靠的双工路径直接处理；WASAPI 端点及其他独立录放设备通过输入 FIFO 和多相 sinc ASRC 汇入输出时钟域。输入文件仍按实际输入采样率保存。ASRC 当前使用平滑的 FIFO 水位 PI 控制，支持不同名义采样率及缓慢时钟偏差，不以周期性丢帧维持同步。ADC / DAC 时间戳已经采集，但尚未实现完整的跨流时间基准拟合。

原生时间线同块混音，循环在采样边界执行，seek 通过代次丢弃旧预读数据。项目位置和持续前进的设备采样计数分开；暂停项目时持续采样计数仍前进。VST3 收到实际 BPM、项目采样位置与拍位置。歌曲的离线效果渲染也传递 BPM 和时间偏移。

## 插件桥接、状态和故障

共享内存两侧均为固定容量 SPSC 队列，每队列最多 128 块，每块 128 帧立体声 float32。Core 不等待 Worker，不在回调内分配内存、读写文件或获取插件锁。设备回调可为非 128 整数倍，适配器会积累连续采样。桥接窗口覆盖至少一个完整设备回调，最低 512 帧；例如 480 帧回调使用 640 帧窗口，1536 帧回调使用 1664 帧窗口。它是稳定性预算，不能宣传为硬件实测往返延迟。

块包含会话代次、序号、项目位置、连续位置、采样率、BPM、拍位置及故障标记。Core 丢弃迟到数据，不重放上一次湿声；欠载时短暂淡出至静音，恢复时淡入。最多保存 256 个缺损区间，并记录溢出的区间数。区间使用输出会话采样坐标，不是已经换算好的录音文件坐标。

Worker 处理异常、非法音频或动态延迟变化时使对应链进入故障状态。原生干声录音不依赖 Worker。Supervisor 有启动、命令和存活检查超时，终止挂起进程，不无限自动重启。动态延迟变化目前要求重新启动链，没有实现并行总线自动延迟补偿。

Windows Worker 的处理线程通过 [MMCSS](https://learn.microsoft.com/en-us/windows/win32/api/avrt/nf-avrt-avsetmmthreadcharacteristicsw) 申请音频任务优先级，退出时撤销；扫描、界面和离线渲染不申请该优先级。注册失败保留普通调度，并在状态中返回结果。IPC 探针单独报告自身调度迟到次数，避免把模拟回调的调度停顿隐藏在音频比较结果中。优先级不能保证未知插件或高负载环境下零欠载。

VST3 保存 component 与 controller 的完整不透明状态；AUv2 保存 ClassInfo。状态采用 SHA-256 内容寻址，加载时验证完整性。实例 UUID 与插件身份分离，支持重复实例。`.bbtone` 版本 2 包含状态数据，保留版本 1 导入能力；不包含第三方插件程序或厂商授权。插件二进制只从本机验证目录解析，工程不直接指定任意动态库路径。VST3 验证二进制指纹，AU 目前验证组件身份、版本及架构元数据。

离线渲染使用相同节点顺序，去除插件算法延迟，不引入实时 IPC 窗口。有限尾音受上限约束，无限尾音同样截到明确上限；当前应用上限为 30 秒，工具允许配置到 120 秒。离线入口返回尾音是否被截断。尚未实现不支持离线模式的插件按实时速度渲染的回退。

## 录音、输出和诊断

所有原生输出回调的返回路径统一经过非法数值处理和按立体声组联动的输出保护，峰值上限为 0.98。诊断分别记录驱动输入溢出、输出欠载、PCM / ASRC 欠载、插件未按时返回、非法样本、限幅衰减、实际回调帧数以及耗时最大值和 P99 / P99.9 桶上界。

军火库显示驱动报告与路径计算的估算延迟；没有把该值标成实体回环测量。正式录音保留未经重采样的 `dry-original.wav`，另生成现有对齐后的源文件与预听文件。原生采集 WAV 预留 RF64 头，可在超出 RIFF 长度时升级；中断恢复检查格式与块边界，截断不完整帧。磁盘错误和提前 EOF 会结束对应操作，避免无限等待。

当前湿声通过保留的干声和状态重新渲染，尚未增加同步写入的独立湿声录音文件，也未记录整个录音期间的逐样本参数自动化。

## 构建与验证入口

依赖固定为 MIT 许可的 VST3 SDK 3.8.0，提交 `9fad9770f2ae8542ab1a548a68c1ad1ac690abe0`。采用 SDK 加 Apple Audio Unit API 的路线；未引入 JUCE。构建把插件辅助进程和 SDK 许可安装到对应平台的 `resources/audio-host`。macOS 仅插件宿主使用关闭 Library Validation 的 entitlement，Electron 权限不扩大。

常规构建使用 `pnpm native:audio` 和 `pnpm build`。在 CMake 配置中启用 `BANDBUDDY_AUDIO_CORE_TESTS=ON`、`BANDBUDDY_PLUGIN_TEST_FIXTURE=ON` 可生成核心探针和 SDK ADelay 测试插件；ADelay 不随产品安装。

| 检查 | 入口及覆盖 |
| --- | --- |
| 应用回归 | `pnpm exec vitest run --maxWorkers 4`，包括设备路由、版本兼容、状态完整性和录音恢复 |
| Core 白盒 | `bandbuddy-audio-core-tests`，输出保护、120 秒模拟时钟漂移、多轨、seek、loop、RF64 |
| 插件实链 | `node scripts/test-audio-plugins.mjs`，真实 ADelay 扫描、加载、参数、状态恢复、共享内存、可变回调、实时与离线比较、Worker 终止后干声继续 |
| 已安装组件 | 测试脚本可通过 `BANDBUDDY_TEST_AUDIO_HOST` 和 `BANDBUDDY_TEST_PLUGIN_HOST` 指向目录包里的可执行文件 |
| 应用服务实链 | Windows 构建测试 fixture 后，设置 `BANDBUDDY_PLUGIN_INTEGRATION=1` 运行 `tests/audio-upgrade.test.ts`；验证目录扫描、指纹、Worker 启停、参数、完整状态及临时映射清理，隔离用户插件目录 |
| 旧原生路径 | `node scripts/test-audio-host.mjs`，模拟录音与已有原生功能 |

ADelay、模拟设备和浏览器 fixture 能验证代码与进程链，不能代替实体声卡试听、真实插件窗口或长期压力测试。

## 后续验收与迁移范围

正式默认启用前，仍需完成以下工作：

- 在 macOS 实际编译和签名包中验证 VST3 / AUv2、麦克风权限、插件授权窗口、生命周期和 Retina；AUv2 的宿主拍速回调仍待补齐。
- 在 Windows 验证代表性商业效果器的原生界面、DPI 切换、反复开关与授权；当前自动化真实插件 fixture 没有编辑器。
- 完成真实声卡的端点稳定身份、拔插恢复、ADC / DAC 时间映射、独立设备长时间漂移及往返延迟测量。
- 将排练室、多通道分流等剩余桌面路径迁入原生图；原生练习室 EQ 当前没有实时频谱数据。正式录音伴奏仍通过既有预渲染路径进入同一设备回调。
- 增加同步湿声文件、录音文件坐标下的故障区间、动态延迟补偿和受控图切换；评估内置长 IR、单声道模型及跨链资源调度。

AUv3、MIDI 乐器、侧链、进程内极低延迟模式和跨架构桥接属于升级方案后续阶段，不是当前效果插件入口的能力。
